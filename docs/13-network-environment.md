# 13 网络环境：为什么有时必须开"全局模式"

> 部分券商与银行的 **App、开户页面、验证码接口在内地网络下无法完成提交**。
> 这一章讲清楚：哪些是**技术问题**（用网络环境解决）、哪些是**申报问题**（必须如实填，工具帮不了也不该帮）。

---

## ⚠️ 先说最重要的三句话

1. **网络环境只解决"打不打得开"，不解决"能不能如实申报"。**
2. **IP 归属地 ≠ 你的居住地。** 用境外节点打开 App，**不等于你可以把自己申报成"现居香港"**。
3. **免费节点会看到你的流量。** 你的证件照片、短信验证码、银行卡号都在里面——这是比开户失败严重得多的问题。

---

## 一、为什么需要它：这是技术问题，不是偏好

内地居民用境外券商/银行 App 时常见的**技术性阻断**：

| 现象 | 原因 |
| --- | --- |
| 页面能打开，但**提交后一直转圈** | 风控/反爬接口在境外网段才正常响应 |
| **验证码收不到** | 短信/邮件接口按出口 IP 做频率与地域判断 |
| **App 闪退或功能灰掉** | 商店区域与 IP 归属地不符，或 App 本身做了地域限制 |
| 提示「**当前地区不支持**」 | 服务端按 IP 归属地直接拒绝 |
| **上传证件一直失败** | 对象存储直传域名在内网不可达 |

**解法**：让设备走**境外节点 + 全局模式**（所有流量都走代理，而不只是浏览器）。

> 💡 **这不是个别现象**：多位用户在 [01 致富证券](guides/01-broker-chief.md) 与 [02 盈立证券](guides/02-broker-usmart.md) 的开户反馈里都提到「**还得设置成全局模式才行**」「科学上网就行了吧」。

---

## 二、全局模式 vs 规则模式

| 模式 | 含义 | 用途 |
| --- | --- | --- |
| **规则模式** | 只有被规则命中的域名走代理（常见：境外网站直连、国内网站走直连） | 日常浏览 |
| **全局模式** | **所有流量**都走代理 | ✅ **开户 App、开户页面、验证码接口** |

**为什么开户必须全局？**
因为提交是**多环节串联**的：App → 对象存储（传证件照）→ 风控接口 → 短信接口 → 提交接口。
**只要有一个环节走了直连，出口 IP 就会在服务端呈现不一致**——这恰恰是风控系统最容易抓的信号之一。

> 🔍 **自己就能验证**：在 App 内打开"我的/设置"看 IP，在浏览器打开 `ipinfo.io` 看 IP，**两者必须一致**。

---

## 三、核心原则：网络环境与申报信息必须自洽

券商与银行的反洗钱审查，会交叉比对**四类信息**：

```
① 出口 IP 归属地        ② 申请表填写的居住地址
③ 上传证件上的地址      ④ 出入境记录 / 住址证明
```

| | 做法 | 后果 |
| --- | --- | --- |
| ✅ **正确** | 用境外节点**解决访问问题**；居住地址**照实填内地**；税务居民**如实申报**；合规申明**照实签署** | 合规，通过率高 |
| 🚫 **错误** | 因为用了香港节点，就把居住地址申报成"现居香港" | 地址与身份证/流水对不上 → 补件或被拒；开户后被查出 → **账户限制或清退** |
| 🚫 **错误** | 在境外网络下申报为"非内地税务居民" | 股息预扣从 10% 变 30%，且属不实申报 |

> ⚠️ **注意逻辑**：网络环境**不可见地**影响审核是常态（App 自动记录），但**地址申报是书面的、可被举证的**。两者不一致时，**永远以书面申报为准**，而书面申报必须为真。

## 四、各平台的实际表现

> ⚠️ 以下为**经验观察**，非官方口径，平台随时会改。**开户前先小成本试一次**（走到能提交那一步再决定要不要投钱买套餐）。

| 平台 | 内地网络直连 | 需要全局模式 | 备注 |
| --- | --- | --- | --- |
| **致富证券** | 注册/资料页可开，**提交环节易卡** | 建议 | 用户反馈中明确提到过 |
| **盈立证券 uSmart** | App 内开户入口**需境外网络** | 建议 | 内地直连常见白屏 |
| **复星国际证券** | 香港 App 需境外网络 | 建议 | 且**须身处香港**完成，见 [12 篇](guides/12-broker-fosun.md) |
| **汇丰 / 中银香港 / 恒生** | App 需境外网络 | 建议 | 且**须身处香港**完成 |
| **ZA Bank / WeLab** | 需境外网络 + **人在港** | 必须 | 且定位校验会拒绝内地 GPS |
| **纯美股券商（IBKR 等）** | 注册/入金可直连 | 一般不需要 | 但**视频核验**环节常需 |

## 五、实操清单（照着做就行）

### 选节点

| 原则 | 说明 |
| --- | --- |
| **优先港/新/日** | 离内地近、时区接近、后续若需"人在当地"时衔接方便 |
| **不要频繁换节点** | ⚠️ **频繁切换 IP 比"一直用某个境外 IP"更可疑**——后者像正常用户，前者像在试探风控 |
| **选稳定线路** | 断了重连如果换到了别的 IP，等于换了一次身份 |

### 全流程的一致性

```
① 开启全局模式，选定一个节点
      ↓
② 确认 App 内 IP 与浏览器 IP 一致（ipinfo.io / ip.sb）
      ↓
③ 用同一个设备、同一个 IP 走完：注册 → 上传证件 → 人脸 → 签署 → 提交
      ↓
④ 提交后保持不变，直到收到审核结果
      ↓
⑤ 拿到开户确认信、核对持牌法团名称后，再考虑是否切回直连
```

| ❌ 别做 | 原因 |
| --- | --- |
| App 用代理、浏览器用直连 | 出口 IP 不一致 |
| 手机开代理、电脑直连，交叉提交 | 同上 |
| 提交到一半切节点 | 中途 IP 跳变，直接进风控视野 |
| 一台设备同时挂多个地区节点 | 系统无法判断哪个是真身 |
| **借别人的网络环境/设备** | 资料与 IP 的归属人不对应，等同于代持 |

### 工具选择

| 要素 | 为什么重要 |
| --- | --- |
| **专用客户端** | 系统代理 / TUN 模式比手动改浏览器代理可靠得多，能覆盖 App 的所有流量 |
| **支持订阅导入** | 换节点、换线路不用反复改配置，减少操作失误 |
| **多端一致** | Windows / Mac / Android / iOS 能用同一订阅，设备间 IP 保持一致 |
| **不要用免费节点** | 🚫 流量可能被中间人监听，**证件照片、验证码、网银密码都在里面** |

## 六、常见问题

**Q：切换了 IP 会不会被拒？**
A：**频繁切换**比"一直用同一个境外 IP"更容易触发风控。开一次户全程用同一个节点，正常不会被拒。

**Q：提交后还需要保持代理吗？**
A：**建议保持到出结果**。审核期间 IP 跳变可能触发二次验证，反而更慢。

**Q：审查期间我换网络了会怎样？**
A：可能收到补充材料通知，或被要求视频核验。**所以提交前要预留一个稳定环境**。

**Q：用的 VPN 合法吗？**
A：需要区分两件事：
- **服务端**：未经批准经营跨境专线/VPN 服务，**这是服务商的违法风险**，与使用者无关
- **使用端**：个人使用非经营性跨境工具，在实践中极少被追责，但**并非没有风险**
- **真正的大风险在别处**：把境外网络用来**伪造居住地/税务居民身份**（见第三章），这是对金融机构的虚假陈述

**Q：开了全局模式，日常生活会不会受影响？**
A：会。内地网站/APP 可能变慢或异常。**建议只在开户时段开全局，其他时间用规则模式。**

## 七、🚫 红线清单

```
🚫 不要用境外网络把居住地址申报成"现居香港/海外"
🚫 不要在境外网络下申报非中国税务居民
🚫 不要使用来路不明的免费节点 / 公共代理（证件与验证码会泄露）
🚫 不要在多台设备、多地区同时登录同一券商账户
🚫 不要用 VPN 规避银行的反洗钱审查
🚫 不要用网络环境绕过平台的"人在当地"要求后仍作不实申报
```
